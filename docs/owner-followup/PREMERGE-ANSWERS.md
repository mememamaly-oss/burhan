## 2) الناجيات التي تمسّ الرفض/القبول/الأصل/التوجيه/النطاق (من أصل 80)
أربعة مواقع فقط من أصل 18 موقع نجاة تمس المنطق. التحليل حرفاً-بحرف:

### الموقع 183 (raw 288-289) — بناء الأصل — لم يكن تجميلياً: قُتل
```
ORIG: body = fetch_well_known(
          "https://" + host if "://" not in base_url else base_url, fetch=fetch)
MUT : body = fetch_well_known(
          "https://" + host if "://" in base_url else base_url, fetch=fetch)
```
حذف `not` يقلب اتجاه الثلاثي: مدخل يحمل مخططاً (http://example.test:8080) يُعاد بناؤه
https:// للمضيف المجرد — الطلب يذهب لأصل خاطئ (يسقط المنفذ والمخطط). **هذه ثغرة اختبار
حقيقية لا مكافئة** — قُتلت باختبار M1 في tests/test_mutation_kills2.py:
- M1: هدف http كامل المخطط يجعل fetch يستقبل أصل http نفسه بالمنفذ
- M1b (توثيقي): الساق المقابلة (بلا مخطط) غير قابلة للوصول عبر authorize أصلاً —
  urlsplit يقرأ "example.test:8080" كمخطط (host=None → رفض upstream)، و"//host"
  لا يحوي "://". verified بالطفر اليدوي: الاختبار يفشل مع الطفرة وينجح بدونها.

### الموقع 72 — فرع IDN — مكافئة، السبب:
```
ORIG: if host and (not host.isascii()):
MUT : if host or not host.isascii():
```
`or` تدخل المضيف الفارغ مسار idna → استثناء يُبتلع (host يبقى كما هو) → authorize
يرفض المضيف الفارغ أصلاً بشيك F1 ("no host"). على المدخلات الممكنة (مضيف موجود
ASCII أو يونيكود، أو فارغ) السلوك الملحوظ متطابق. المكافئة موثقة في docstring
الملف نفسه.

### الموقع 137 — عائد القبول self-hosted — مكافئة، السبب:
```
ORIG: return (True, "...EXPLICIT lab mode (self-hosted fixtures: %s)"
              % ", ".join((t.get("covers") or [])[:3]), t["id"])
MUT : نفس السطر مع (t.get("covers") and [])[:3]
```
القرار (True) والإدخال (t["id"]) لم يتغيرا؛ الطفرة تبدل وصف covers في نص الرسالة
(قائمة فارغة دائماً بدل أول 3 عناصر). الرسالة نص تشخيصي، والقرار الملحوظ —
الثلاثية (ok=True, eid) — متطابق.

### الموقع 178 — عائد رفض hah الخطاب — مكافئة، السبب:
```
ORIG: return (False, "...sha256 does not match (%s != %s)"
              % (t["id"], got[:12], want[:12]), t["id"])
MUT : نفس السطر مع got[:13]
```
الرفض (False) ثابت؛ الطفرة تزيد اقتطاع عرض الهاش في نص الرسالة من 12 إلى 13 حرفاً.
تجميلي بحت — لا يغيّر أي قرار.

**الباقي (56 طفرة على 14 موقعاً):** نصوص بانر وflush وحدود قراءة/اقتطاع (74/75،
200000/200001، 300/301، MAX_BODY+1/+2) وقيم افتراضية للتوقيع ومساعد الحل —
التصنيف الكامل في MUTATION-CLASSIFICATION.md.

## 3) الوضع المختبري — ما الذي يتجاوزه بالضبط، بالاختبار
**يتجاوز شيئاً واحداً بالضبط:** اشتراط إثبات "self-hosted fixtures" للأهداف
loopback/الخاصة (فرع `_is_loopback_or_private(host)` في authorized_targets.py).
هذه الأهداف تجيب على آلة المشغل نفسها — الملكية هي حقيقة تشغيلها.

**لا يمسّ أبداً:** إثبات أي نطاق عام (well_known / scope_page / dns_txt /
signed_letter يبقى إلزامياً حرفياً مع الوضع مفعّلاً).

الاختبارات (tests/test_lab_mode_boundaries.py — 8/8 خضراء، كل اختبار مسمى
بالطفرة التي يقتلها):
- **(أ)** LAB-A1: هدف خاص لا يستشير إدخالات العامة إطلاقاً (لا fetch عام ينطلق)؛
  LAB-A2/A2b: هدف عام مع الوضع مفعّل يُرفض بلا إثباته ويمرّ به فقط (entry id
  نفسه)؛ LAB-A3/A4: الوضع وحده لا يخوّل مضيفاً عاماً ولا خاصاً بلا إدخال.
- **(ب)** LAB-B1: stats.lab_mode = {active, via} موجود في كل تقرير (فحص حقيقي
  على خادم loopback حي، بالحالتين on وoff — قتل سطر التسجيل يسقط المفتاح
  فيفشل الاختباران معاً)؛ LAB-B2: بانر التفعيل على stdout
  (`[authorized-targets] ... EXPLICIT lab mode ...`) + stats.lab_mode في ملف
  التقرير — مؤكدان e2e (owner init → scan → rc 0).
- **(ج)** LAB-C1 (حد المحرك): --lab/BURHAN_LAB_MODE لا يمكن أن يحمل مضيفاً
  عاماً معادياً عبر البوابة بلا إثباته. الطرف TypeScript (route.ts) مقيد بثابت
  DEMO_TARGET_URL والجسم مُهمَل — مثبت e2e بـdemo.integration.test.ts
  ("HOSTILE body still scans ONLY the platform fixture") وحد allowPrivate في
  normalizeScanSettings قرار خادمي لا يدخله العميل.
